# HANDOFF — RUN AT END OF SESSION

When Dr Sarah says **"Run handoff"**, act as both Study Partner and Study Coach.

## Step 1 — Capture the session
Read the latest repository state. Convert today's conversation into a structured study log containing:
- date
- topics/subtopics covered
- resources used
- questions attempted and performance
- mistakes and reasoning errors
- concepts Sarah could explain
- unresolved gaps
- revision items
- next-session recommendation

Do not invent missing data. Mark unknown fields as unknown.

## Step 2 — Update learning state
Update the relevant progress and weak-area records. Distinguish exposure/read from question-practised and demonstrated understanding.

## Step 3 — Coach review
Review the cumulative state and determine whether the existing roadmap still fits. Check workload, topic balance, question coverage, repeated mistakes and overdue revision. If a change is warranted, state exactly what should change and why. If not, explicitly state that no roadmap change is indicated.

## Step 4 — Persist
Update the appropriate Markdown files in GitHub. Keep the structure Obsidian-friendly and links consistent. Do not delete useful history; append or update the current-state files while preserving dated logs.

## Step 5 — Report back
Return a compact handoff summary:
1. Completed today
2. New weaknesses
3. Questions performance
4. Revision due
5. Coach decision
6. Next session
7. Files updated

## Evidence rule
Never turn an unsupported medical statement into a repository fact. Preserve citations/source attribution for substantive medical content. If a claim lacks a reputable source, mark it unverified rather than inventing one.
